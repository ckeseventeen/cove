## 架构规划与已落地边界

- UI：App 负责导航与聚合状态；views 负责页面；播放器、影片详情、目录浏览、确认弹窗独立组件。纯文件名解析位于 lib/media.ts，避免 UI 同时承担解析规则。
- 应用层：Rust commands 按 accounts、library、playback、metadata、transfers 拆分；lib.rs 保留初始化、注册和生命周期。后续将公共通配导入改为显式依赖，并进一步提炼服务接口。
- 数据层：Store 管事务与迁移；source_files 表达同文件多来源。下一阶段应建立持久化 Work/Season/Episode/Edition 模型，当前前端分组还不是领域数据库。
- 外部系统：credentials 集中凭据获取与刷新，direct/webdav 隔离协议。下一阶段统一 Provider 能力接口，取消散落的 provider 字符串分派；同账号刷新独占，不同账号可并行。
- 播放器：PlayerController 统一串行控制及快照；原生视频视图与 Web 控制层分离。下一阶段完善进程退出时 mpv/render 生命周期释放与真实状态机集成测试。
- 元数据：当前全局锁保证一致性，但冷请求会串行等待。后续改为按文件/匹配键 single-flight，并拆分海报与歌词获取状态及 TTL。

## 验证边界

前端测试、TypeScript 构建、Rust 回归和打包检查以本轮实际执行结果为准。浏览器演示数据只用于布局，不代表真实云盘播放成功；解析微基准不代表整库性能。真实账号上传/复制冲突策略、网络中断、超长媒体、HDR、外置显示器和干净机器安装仍需要集成验收。
